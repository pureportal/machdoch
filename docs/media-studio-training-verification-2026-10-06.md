# Media training verification — 2026-10-06

The training workflow now integrates Stable Diffusion 1, Stable Diffusion 2, SDXL, and Pony with LoRA, denoiser finetuning, and textual inversion. SD3 adds LoRA and transformer finetuning. Krea 2 RAW retains its upstream LoRA trainer. The broader goal of training every eligible open model is **incomplete**: the remaining transformer, video, and audio families still require training integrations and real-model verification.

## Implementation

Basic training selects an installed base model, method, concept, trigger, and images. Advanced controls expose precision, batch size, gradient accumulation, learning-rate scheduling and warmup, weight decay, gradient clipping, Min-SNR weighting, noise offset, LoRA dropout and target layers, aspect buckets, gradient checkpointing, and checkpoint retention. Embedding training requires an initializer word and a single token.

One Stable Diffusion runtime handles the four related UNet architectures. SD3 uses its own three-encoder conditioning and flow-matching objective. Both share the optimizer and checkpoint loop, cache latent distributions and frozen text conditioning, sample fresh latent noise for each batch, and save optimizer, scheduler, scaler, and random state in atomic checkpoints. Resume checks the dataset, model identity, and settings. Loss, learning rate, elapsed time, and estimated remaining time are recorded per optimizer step.

Model loading, image preparation, checkpoint saving, and weight export appear as current job status. Embedding loading registers and copies the supplied vectors without computing vocabulary-wide initialization statistics; profiling the preceding implementation identified that calculation as an avoidable delay. Existing vocabulary rows and case-sensitive multi-vector aliases are checked separately.

Finetuning updates every denoiser parameter; the VAE and text encoders remain frozen. It exports a complete safetensors Diffusers package. LoRA exports attention and optional feed-forward adapters. SD3 includes joint attention and context feed-forward targets. Textual inversion exports the single CLIP embedding for SD1/SD2 or both CLIP embeddings for SDXL/Pony; it is not integrated for SD3. The interface imports each artifact through its corresponding model or addon route. Using a trained addon in Basic selects its original installed training base and checks that it remains runnable and compatible.

## Research

The [Diffusers training overview](https://huggingface.co/docs/diffusers/main/en/training/overview) describes architecture-specific examples and memory optimizations. Its [SDXL training documentation](https://huggingface.co/docs/diffusers/main/en/training/sdxl) and [textual inversion documentation](https://huggingface.co/docs/diffusers/main/en/training/text_inversion) informed conditioning, trainable parameters, and export handling. [Min-SNR weighting](https://arxiv.org/abs/2303.09556) informed the optional loss weighting. [OneTrainer](https://github.com/Nerogar/OneTrainer) and [AI Toolkit](https://github.com/ostris/ai-toolkit) informed the separation between a simple starting workflow and detailed training controls.

The runtime uses the pinned Diffusers revision `4295ee3ec58efa6577bc459e9b84ca3f63aa9a96`. The earlier [upstream trainer audit](media-studio-training-research-2026-10-04.md) records concrete candidate routes for the remaining families. An upstream trainer is not evidence that Machdoch can execute, export, import, and generate with it.

The pinned [SD3 DreamBooth LoRA example](https://github.com/huggingface/diffusers/blob/4295ee3ec58efa6577bc459e9b84ca3f63aa9a96/examples/dreambooth/train_dreambooth_lora_sd3.py) informed the shifted and scaled latent distribution, sigma interpolation, and velocity target. Its source is retained as `upstream-sd3-training.py`. The integrated objective samples scheduler positions uniformly and minimizes the velocity error directly; Min-SNR and quantized training are rejected for this runtime.

A renewed primary-source check found that [Musubi Tuner](https://github.com/kohya-ss/musubi-tuner) documents separate Qwen, Z-Image, FLUX.2, Wan, HunyuanVideo, FramePack, and MiniMax-H3 trainers. Its 12 GiB image, 24 GiB video, and 64 GiB RAM figures are recommendations, not proof that lower-memory training is impossible; it also describes swapping and offloading. The [LTX publisher trainer](https://github.com/Lightricks/LTX-2/blob/main/packages/ltx-trainer/README.md) specifies Linux/CUDA and a 32 GiB low-memory configuration, which this Windows/AMD host does not meet. These routes still need architecture-specific datasets, objectives, artifact conversion, and local validation before integration.

## Hardware limit

This machine has 15.922 GiB of GPU memory and 31.310 GiB of physical RAM. The installed SDXL checkpoint contains 2,567,463,684 UNet parameters. FP32 trainable weights, gradients, and two AdamW moment tensors require at least 38.258 GiB, before activations and the other pipeline components. The trainer checks that lower bound before conditioning preparation or optimizer allocation and tells the user to use LoRA or a device with more memory. The real SDXL and Pony finetune attempts both reached this guard. Production denoiser finetuning for these two checkpoints cannot be validated on this host with this optimizer.

Native Cargo verification initially encountered a Tauri command registration error and a missing `resources/speech/phonon2/model` packaging input from separate workspace work. The command registration was corrected. A test-only `TAURI_CONFIG` resource list bypassed the unprepared speech bundle. `cargo check --tests` passed, but linking the test executable failed with 85 unresolved Whisper and ONNX Runtime symbols. A later retry reproduced the same linker failure after waiting for the shared Cargo build lock. Native lifecycle/import tests and a complete desktop installer remain unverified.

The failed linker command omits both native libraries. Cached Whisper build output has no native link directives. Both dependency build scripts skip linking when `DOCS_RS` is set; the current environment has no such setting, so a stale documentation build is a possible cause rather than an established attribution. A fresh isolated dependency build then failed at `whisper-rs-sys`'s required Vulkan SDK check: `VULKAN_SDK` is unset and no SDK installation was found at the standard location. Its output is retained in `native-dependency-probe.log`. The ONNX Runtime link failure still needs a successful native executable to resolve. Diagnostics use a separate target directory under `C:\Development\machdoch-verification\2026-10-06-training`; the shared build cache was left intact.
