# Media Studio connected workflows — 2026-09-14

This pass implements connected Advanced workflows and verifies them against the running Windows desktop backend. The earlier [fix report](media-studio-fixes-2026-09-14.md) and recent source changes were inspection context, not evidence of success for these new paths.

## Changes

- Added **Generate prompt**, **Select objects · SAM3**, **AI upscale**, and **Refinement loop** nodes, with four editable templates: **Change selected object**, **Replace background**, **Generate until checks pass**, and **Upscale and animate**.
- Added a native workflow executor for sequential local image generation, editing, transformations, technical analysis, gates, and image-to-video generation. Each generation step resolves its own model and consumes its connected prompt, images, references, mask, and seed. Runs use the saved canonical revision and retain intermediate assets, source lineage, node attempts, generated prompts, and gate decisions.
- SAM3 produces a typed mask connection and passes through the original image. Text queries support all, largest, or best matches, inversion, confidence, grow, and feather. The edit worker checks mask/source identity, preserves original framing, and composites only selected pixels. Empty masks fail. Preflight rejects conflicting painted/connected masks, lossy masked output, and masked background removal.
- Added local Qwen3 prompt generation and Spandrel upscaling. Managed downloads for Qwen3-0.6B and Real-ESRGAN use pinned revisions, expected sizes, SHA-256 verification, and resumable component acquisition. Advanced users can choose another local text-model folder or supported Spandrel weight file. Upscaling supports 2×/4× output, bounded tiled inference, and alpha preservation. Spandrel is included in runtime setup requirements.
- A single image connection now supplies the image-to-video endpoint correctly. Model-specific video settings survive compilation and native request construction. The tested path produces an opaque Hunyuan WebM and can save both the upscaled image and video.
- Gates compare the actual image/report identity and technical measurements against configured minimum dimensions and clipping thresholds. Inconclusive checks can stop or continue; failed checks can stop or repeat. A loop has an explicit start step, at most 20 attempts, a seed increment, and optional prompt feedback. Unaffected prerequisites remain cached. Repeated output branches cannot bypass their retry gate. Cancellation uses the existing native cancellation path.
- Quality-gate rejection has its own validation error. Activity shows the measured failure and asks the user to review the image and gate settings; it no longer presents an exhausted gate as an internal error or a safe automatic retry.
- Model selection is accessible in the main node settings. File/folder pickers and model acquisition actions sit beside the relevant settings; confidence, tiling, and token limits remain in advanced groups. Nodes show intermediate previews, and their inspectors expose generated prompts and gate results. Output counts exclude intermediate images/reports. Template and history copy was reduced.

The existing Basic, single-stage generation, model acquisition, editing, asset, and export paths remain in place. No duplicate development services were started. Existing workspace changes were preserved.

## Limits and remaining verification

**SAM3 inference is blocked by model access.** The official `facebook/sam3` repository requires access approval; this environment has neither its weights nor credentials granting that access. The UI offers **Get SAM3 access** and a model-folder picker, and correctly disables Run without a model. Its settings and typed connections were inspected, and its mask processing/handoff has unit coverage. The complete generation → actual SAM3 → edit path was **not** run. The real dress and background tests used painted masks; they do not establish SAM3 segmentation quality or native SAM3 mask handoff.

Quality gates currently measure technical dimensions and clipped pixels. They do not judge prompt adherence, object identity, aesthetics, edge halos, or unwanted extra handles. The background halo and Basic mug result demonstrate that limitation. The measured checks can reject unsuitable output and bound retries, but they do not guarantee that another attempt will improve it.

Loops rerun the selected region using cached upstream inputs. They do not automatically feed the previous attempt's image back into the next edit. Prompt feedback applies when the repeated start is a prompt/image generation or editing step. In the verified generative retry, feedback did not change Qwen's wording. Automatic acceptance after a failing generation was not demonstrated; first-attempt acceptance, repeated rejection, hard attempt limits, and cancellation were demonstrated separately.

Connected generation currently uses local models and one raster candidate per generation step. New connected cloud, batch-candidate, or human-review execution paths were not added. Existing separate remote/review paths are outside this verification pass. Real upscaling used the installed Real-ESRGAN 4× model at requested 2× output. Other Spandrel architectures, 4× final output, other text models, real SAM3, transparent/native-loop video, and other hardware remain unverified. LoRA/embedding application, WAN rendering, SVG generation, damaged-runtime repair, packaged builds, and other platforms were not reverified here; earlier results must be consulted independently.
