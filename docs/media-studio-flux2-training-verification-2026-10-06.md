# FLUX.2 training verification — 2026-10-06

Four FLUX.2 Klein variants now have LoRA, denoiser finetuning, and input-vector embedding workflows. Publisher Klein Base 4B LoRA, embedding, and denoiser training completed on the local AMD RX 9070. All three passed native import and generated inspected images with exact source/managed pixel agreement. A fresh pair of publisher finetune requests also passed with pipeline reuse and identical pixels. An earlier repeated request crashed after sampling under severe host memory pressure; its cause remains unresolved. Reduced finetune/embedding workflows also passed native import and managed generation. Z-Image Base publisher LoRA generation completed after precision and offload fixes.

The full goal remains **incomplete**. The [coverage inventory](validation/training-flux2/coverage.json) records 52 generation architecture identifiers, 17 with training routes, including the Krea RAW alias, and 35 without trainers. Integration counts do not establish real-weight verification or learned quality for every variant.

## Implementation and research

The pinned [Diffusers Klein trainer](https://github.com/huggingface/diffusers/blob/4295ee3ec58efa6577bc459e9b84ca3f63aa9a96/examples/dreambooth/train_dreambooth_lora_flux2_klein.py) informed deterministic VAE encoding, patchification and batch-normalization statistics, packed latent positions, timestep scaling, and Qwen3 conditioning from hidden layers 9, 18, and 27. The downloaded script matched Git blob `3cad3f2ac561db89d7de24e31f2779bd8bb3e865`. The [Base 4B publisher recipe](https://huggingface.co/black-forest-labs/FLUX.2-klein-base-4B/blob/a3b4f4849157f664bdbc776fd7453c2783562f4d/README.md) informed BF16 inference, 50 steps, and guidance 4.

The shared flow trainer now handles `flux-2`, `flux-2-klein-base-4b`, `flux-2-klein-9b`, and `flux-2-klein-base-9b`. `flux-2-dev` remains unintegrated. LoRA includes joint attention and fused single-block projections, with optional feed-forward targets. Attention-only mode masks the feed-forward rows and columns within the fused projections, including their gradients; exported adapters retain zero updates in those regions. Finetuning updates the denoiser and exports a complete pipeline with its exact architecture and distilled state. Embeddings train one Qwen3 input vector, export `flux2_qwen3`, preserve case-sensitive aliases, and reject truncated tokens. Native import recognizes the vector profile and verifies it again before generation.

Native adapter classification recognizes both the 4B and 9B projection widths. The public [9B KV configuration](https://huggingface.co/black-forest-labs/FLUX.2-klein-9b-kv-fp8/blob/31acba2ee2e53472726fe49b2b0af0137ad41ecd/transformer/config.json), together with the pinned transformer's fused projection construction, establishes the 4,096-wide tensor contract. This is structural evidence, not a test with the gated 9B publisher weights. Complete pipeline exports clear unused accelerator allocations and use a 1 GB shard target through the pinned Diffusers save API; an indivisible tensor can exceed that target.

Klein and Z-Image training and embedding inference request only one token's unused vocabulary logits from Qwen3 while preserving all hidden states. The pinned Qwen3 API supports this directly. Exact conditioning comparisons and gradient/resume checks verify the useful outputs; this reduces the otherwise unused 512-token language-head output and does not establish a measured end-to-end speedup. Ordinary pipeline prompt encoding is unchanged.

Readiness probes now allow 30 minutes, matching the generation startup budget. An observed cold Torch import exceeded eight minutes on this host, beyond the previous three-minute readiness limit. Native verification of the installed runtime passed imports, computation, and video encoding in 168.919 seconds in a different cache state; this does not establish cold-start speed.

A reduced Base 4B finetune also passed two native resident-worker requests on the RX 9070. The first took 185.705 seconds including SDK startup; the second reused the pipeline and took 2.494 seconds. Both produced identical pixels, and explicit worker release passed. This verifies cache behavior for the small fixture, not publisher-model throughput or quality.

Basic and Advanced use the existing training workflow, original-base selection, artifact import, and checkpoint controls. The new module is included in the desktop resource bundle. Package inspection detects 4B/9B projection widths and Base/distilled state, rejects a contradictory trained marker, and rejects importing a detected variant under another name. The publisher Base 4B index omits `is_distilled`; inspection uses the pinned pipeline's `false` default. Inspection of the actual publisher source and tests for all four variant contracts passed. All four variants passed native publish, resolve, and reimport checks; publication now uses the canonical architecture family, including the built-in distilled 4B variant. Klein Base negative prompts and embeddings are encoded through `negative_prompt_embeds`; the pinned pipeline has no `negative_prompt` argument. Inference encoding runs without gradient tracking. Embedding validation counts the actual chat-template tokens in both channels, so an alias that fits plain tokenization but is truncated after formatting is rejected. Distilled variants reject negative conditioning with a recovery message.

Z-Image generation now uses streamed offload with one block per group. A reduced BF16 run with the actual trained publisher adapter produced exactly matching reference latents. A full FP16 run completed sampling but produced nonfinite pixels and was rejected. Z-Image and Klein now default to BF16 on capable CUDA devices and FP32 otherwise; explicit training precision is preserved. The [Z-Image publisher recipe](https://huggingface.co/Tongyi-MAI/Z-Image/blob/04cc4abb7c5069926f75c9bfde9ef43d49423021/README.md) specifies BF16 and distinguishes Base from Turbo.

## Remaining work

Publisher 4B finetune native import/reimport passed in 5,467.410 seconds under heavy storage contention. The first managed native request passed in 2,103.685 seconds and matched the source pixels exactly. Source generation completed at 512×512, 50 steps, guidance 4, with all components BF16 and the full 3,875,544,576-parameter transformer. Requested latents were `[1, 1024, 128]`; peak allocated/reserved bytes were 8,457,594,880 / 8,493,465,600. The source worker recorded 3,426.109 seconds under heavy external-drive contention. The [finetune sample](validation/training-flux2/klein-base4b-trained-finetune.png) contains a coherent red teapot and white cup. Real 4B distilled and both 9B training workflows remain unverified. Retention of distilled generation quality is unverified.

The initial repeated native request spawned a new worker, completed all 50 sampling steps, then crashed with `0xC0000005` in Torch's CPU allocation/copy path after 1,322.207 seconds. It saved no second image. Available physical RAM reached 255,770,624 bytes; 54 of 144 observations fell below the native retention threshold of 2 GiB. A concurrent native compilation explicitly failed to allocate 2 MiB and was rerun separately. The evidence establishes severe memory pressure, but not the Torch crash's root cause or the reason the first worker was evicted. The failed native test and diagnostics are retained, and all its owned worker processes were observed released.

A fresh native pair passed after this task's compilation and downloads finished: 927.604 seconds for the first request and 599.136 seconds for the second, which reused the pipeline. Both images matched the source pixels exactly; explicit release passed and all owned worker processes were observed gone. Memory observations still reached 45,801,472 available physical bytes and 469,168,128 free virtual-memory bytes, with 19 of 305 samples below the retention threshold while work was in flight. The second request waited in a GPU timestep operation before completing. This establishes one successful full-model cache/repeated-generation flow, not sustained reliability or a controlled speed improvement. The earlier crash remains a repeatability risk, and the observed full-model latency is substantial.

The publisher finetune reached step 2 with losses 1.041888 and 0.213821. Its first complete-pipeline export was interrupted after slow USB writes were observed at 2.2 MB/s with queue depth 17, while the SSD had 1.7 GB free. The partial export was retained in `interrupted-export`, and the canonical trainer was restarted with `resume=true` from checkpoint 2. Restore and complete export finished with `resumed: true` and 3,077.172 seconds recorded for the resumed trainer invocation; this duration includes export rather than additional optimizer steps. The trained transformer was staged on the SSD, then copied into ordinary files with matching source/destination SHA-256 for all nine shards. That transfer and verification took 3,191.308 seconds; source staging was later archived on the external drive to recover SSD space; the original materialization record retains its historical SSD path. Peak allocator accounting reached 17,188,269,568 allocated and 19,644,022,784 reserved bytes, exceeding physical GPU memory; this does not establish a workflow contained entirely within VRAM.

The first managed publisher embedding run completed all 50 sampling steps, then exited with `0xC0000005` in Torch's native CPU allocation/copy path before saving an image. Its log is retained as `flux2-publisher-managed-embedding-generation.log`. A fresh run with Python crash diagnostics exited successfully, preserved the managed vector identity, and produced pixels identical to the source run. It recorded 8,318,857,216 allocated and 8,336,179,200 reserved bytes. Its 767.703-second worker duration includes slow runtime imports; initial Torch startup is outside that timer. The original native crash remains unexplained and is a repeatability risk.

The 4B denoiser has 3,875,544,576 parameters. AdamW's weight/gradient/moment lower bound is 57.750 GiB. BF16 Adafactor's implemented estimate is 15.710 GiB before activations, almost the entire local GPU. The publisher embedding's frozen denoiser and encoder alone require about 14.711 GiB at BF16. These estimates do not prove that a full training step fits.

Their reduced checks are not pretrained verification. Full-size SD2, Krea RAW, Z-Image embeddings/finetuning, and many derivatives remain unverified. The current dataset workflow accepts 3–50 captioned images; larger datasets and other modalities require further work.
