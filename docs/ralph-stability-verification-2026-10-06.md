## Changes

- Journal append retries use a known byte offset. Short writes are completed, interrupted partial writes are removed before retry, and a transient flush failure retries the flush without appending the record twice. Failed rollback refuses further appends until initialization repairs the journal.
- Journal initialization reads bounded chunks and validates checksums and sequence order without retaining the entire history. It repairs only an incomplete final record. A valid record missing its newline is terminated before the next append; corruption in a terminated record remains an error. Entries have an eight MiB storage limit. Explicit `readJournal()` still returns the requested complete history.
- Reporting-log sequence recovery streams both logs instead of loading both files into memory. Missing logs begin at zero; other I/O errors remain visible. Malformed reporting records do not invalidate the separate durable journal.
- Windows Git operations enable long paths per command, preserve the original failure and stderr, and have a finite 120-second default timeout. Repository configuration is unchanged.
- Worktree preparation permits at most three attempts after a timed-out preparation mutation, with bounded backoff and jitter. Cleanup must first prove ownership and complete successfully. Invalid metadata, foreign candidates, permanent failures, and failed cleanup are not automatically retried.
- Integration creates its verification candidate inside the cleanup boundary. A timed-out checkout is retried only after removing its registered detached candidate, including a locked candidate. Three failed preparations exhaust the retry budget. Cancellation, a foreign branch, an unregistered directory, or failed cleanup prevents automatic repetition. Preparation and cleanup failures are retained together.
- Isolated startup persists its checkpoint before setup and holds the existing run-mutation lock. Resume checks the saved graph, workspace, checkpoint fence, and independent lease. Changed graphs and live owners cannot be overwritten. Instruction preflight establishes the first execution boundary after preparation; existing executed-checkpoint rules remain in force.
- Interrupted setup has a durable ownership manifest. Recovery verifies the derived paths, branch, repository, and expected branch head before removing a registered checkout. An unregistered directory, foreign branch, changed head, or mismatched manifest remains intact. A successful ownership record is retained if removing the completed setup marker fails.
- Mutation locks held by a confirmed dead PID can be reclaimed immediately after checking the ownership token again. Fresh locks with live or incomplete ownership information remain protected.
- Desktop run/resume commands have a three-attempt recovery controller. A fresh run receives its identity before launch; the CLI consumes that private launch value before loading configuration so nested commands cannot inherit it. Unexpected child exit or a checkpoint-bearing crash triggers inspection of the same saved run, followed by resume when needed. Completed, stopped, blocked, and input-waiting states are reconciled without replay. Cancellation prevents restart; runtime limits and scope are preserved, and submitted input is not repeated. Inspection has a one-minute deadline. A missing or malformed response is reconciled even when the child exits successfully. Inspection failure stops recovery and retains the original error.
- Native integration fixtures now pass Vitest's cancellation signal to commands and settle outstanding work before deleting their directories. This addresses an unhandled `spawn git ENOENT` after a timed-out case, consistent with cleanup removing its still-active working directory. Test budgets are finite and allow multiple commands with the production 120-second per-command limit.

Journal tests cover flush retries, partial writes, failed rollback, Unicode across read boundaries, torn tails, valid unterminated tails, sequence continuation, and corruption. Git tests cover retained timeout/cancellation diagnostics, successful preparation recovery, finite exhaustion, literal staging, and long Windows paths.

## Research

[Temporal retry policies](https://docs.temporal.io/encyclopedia/retry-policies) distinguish operation retries from restarting an entire workflow and support bounded backoff and non-retryable failures. [AWS guidance on idempotent retries](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/) explains why uncertain side effects must be reconciled before repeating an operation. These principles informed byte-offset journal recovery and retrying preparation only after confirmed cleanup; committed flow operations are not replayed to recover setup.

[Git for Windows long-path guidance](https://gitforwindows.org/git-cannot-create-a-file-or-directory-with-a-long-path.html) documents `core.longpaths` and its limitations for scripted commands. [Git configuration documentation](https://git-scm.com/docs/git-config) documents per-command overrides. The implementation applies the setting only to RALPH's canonical Git commands, and verification exercises built-in checkout/removal operations. It does not claim to repair arbitrary external scripts.

[Git worktree documentation](https://git-scm.com/docs/git-worktree.html) requires specifying `--force` twice to remove a locked worktree. Integration cleanup now does this after checking that the expected registered candidate is detached. It leaves an unregistered directory or a candidate assigned to another branch intact.

The historical native exit value is hexadecimal `0xC0000409`. [Microsoft's fast-fail documentation](https://learn.microsoft.com/en-us/cpp/intrinsics/fastfail?view=msvc-170) describes the fail-fast exception family and its first exception parameter. [Microsoft's explanation of the status name](https://devblogs.microsoft.com/oldnewthing/20190108-00/?p=100655) cautions that the code does not establish a stack overrun. No matching Application crash events or archived WER report were recovered for the inspected dates; the dump and exception subcode remain unavailable. Its precise cause is unestablished.

[Node's child-process documentation](https://nodejs.org/download/release/latest-jod/docs/api/child_process.html) distinguishes process exit from closed output pipes. Native supervision reaps descendants and collects output before deciding on recovery; fresh harnesses wait for closed streams when reading responses. [Vitest's cancellation guidance](https://v4.vitest.dev/guide/test-context) documents the test signal used to stop native fixture operations after timeout or cancellation.

[Microsoft's path-length documentation](https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation?tabs=powershell) describes the 260-character `MAX_PATH` limit and application-specific opt-in. [CMake's object-path documentation](https://cmake.org/cmake/help/latest/variable/CMAKE_OBJECT_PATH_MAX.html) describes path shortening for object files. The native verification failure reported a 264-character PDB path; using a shorter owned build target passed that compiler check. This supports a path-length explanation for this verification failure, rather than establishing the historical native crash cause.

A further real-provider recovery failure reproduced after packaging: the canonical instruction digest and Codex probe evidence stayed identical, but the suppressed Codex configuration changed from 26,131 to 25,827 bytes. The [diagnostic reconstruction](../.tmp/ralph-boundary-diagnostic-20261006.json) matches the original environment digest by changing only that byte count. The [first multi-step recovery campaign failed](../.tmp/ralph-desktop-provider-run-20261006.json) because this irrelevant difference paused resume. Environment digests now omit the digest and byte count of suppressed native sources in both fresh resolution and frozen-set adaptation. Their path, convention, discovery status, active native content, model budget, runtime probe, and canonical instructions remain bound. The new regression failed before this fix and passes afterward; existing relocation and active-content checks remain effective.
