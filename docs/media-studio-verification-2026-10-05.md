## Lip-sync probe and research

The downloaded MuseTalk 1.5 UNet, VAE, Whisper, and face parser ran on the actual AMD Radeon RX 9070. The initial probe failed when upstream code redundantly loaded a legacy tar-format ResNet checkpoint before loading the complete trained face parser. The probe instead loads that backbone from the trained parser with `weights_only=True` and strict key checking. The retry produced 50 frames at 25 fps, a two-second silent WebM, in 377.292 seconds inside the probe. All frames changed, and inspected input/output frames retained coherent face geometry with a softer, changed mouth. Audio/video alignment, identity across the full clip, and perceptual lip-sync quality have not been established. This prototype is outside the application; no native lip-sync feature is claimed. Evidence remains in the earlier `mixed-media` directory as `musetalk-probe.json`, `musetalk-silent.webm`, and input/output PNGs; retry logs use the new artifact root.

Primary sources were checked again: [Krea 2](https://www.krea.ai/krea-2-open-source), [MiniMax H3](https://huggingface.co/MiniMaxAI/MiniMax-H3), [Wan 2.2](https://github.com/Wan-Video/Wan2.2), and [MuseTalk](https://github.com/TMElyralab/MuseTalk). Wan's published S2V single-GPU recipe specifies 80 GB GPU memory. This machine exposes 17,095,983,104 bytes on its discrete GPU and approximately 32 GiB system memory; that published recipe cannot be verified here. Reduced-memory implementations have not been established by this run. MuseTalk supplies a separate video-plus-audio route and documents training, but neither establishes an application integration or universal output quality.
