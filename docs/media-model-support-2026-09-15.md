## Implementation

- SD 1.5 and SDXL/Pony verification automatically installs pinned, checksummed tokenizer and pipeline configuration files. The generation worker remains offline.
- SD 1.5 uses IP-Adapter Plus for subject references. SDXL/Pony also expose style and composition roles through separate attention blocks. References can accompany a base image and painted mask, with up to three references and independent influence controls. Adapter and vision-encoder weights install automatically when needed.
- KREA2 base images are encoded by its existing Qwen-Image VAE. Edit strength chooses the final portion of the original noise schedule. Masked sampling restores the source outside the selection at every denoising step; final compositing preserves the original pixels outside the painted mask.
- KREA2 references use its existing Qwen3-VL vision encoder. Each image contributes visual tokens to the twelve hidden-state layers consumed by KREA2. Reference roles enter the encoder prompt; up to three references can accompany a base and mask. Per-reference weights remain unavailable.
- The catalog, Basic controls, Advanced compiler, native execution checks, packaged worker resources, and conditioning evidence agree on these capabilities. Basic hides edit strength for reference-only IP-Adapter and KREA2 requests.
- Transparency continues to use the existing subject-cutout stage. A masked edit and background removal remain separate operations because removing the background changes pixels outside the mask.

The relevant implementations use different kinds of image conditioning:

| [ComfyUI KREA2 encoder](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy/text_encoders/krea2.py) and [KREA explorations](https://github.com/fblissjr/krea-explorations/blob/main/docs/krea2_text_encode.md) | Reference images pass through the Qwen3-VL vision path                                             | References provide semantic visual conditioning. This does not establish exact identity copying or an edit-trained reference-latent pathway.     |
| [Diffusers IP-Adapter](https://huggingface.co/docs/diffusers/using-diffusers/ip_adapter) and [ComfyUI IPAdapter Plus](https://github.com/cubiq/ComfyUI_IPAdapter_plus)                                            | CLIP vision embeddings condition denoiser attention; compatible with image-to-image and inpainting | SD families gain supplemental references instead of treating the sole reference as the image-to-image starting canvas.                           |

The SDXL style and composition controls use the documented up-block and down-block configuration. SD 1.5 exposes subject conditioning only; SDXL-specific block choices are not applied to it.

[Diffusers' SDXL guide](https://github.com/huggingface/diffusers/blob/main/docs/source/en/api/pipelines/stable_diffusion/stable_diffusion_xl.md) documents 768–1024-pixel image editing. The first masked SDXL/Pony trials exposed a shared problem: the existing crop path reduced a small selection to roughly 300 pixels even when a larger inference canvas was requested. Both models produced severe color artifacts in the selection. This also occurred without an IP-Adapter on both SDXL and Pony, so it was not solely a reference-mixing failure. SD 1.5/SDXL crops now scale to fit the requested inference canvas before sampling, then return to the original canvas for compositing.

The [Pony publisher card](https://civitai.com/models/257749?modelVersionId=290640) specifies the penultimate CLIP layer, commonly called “clip skip 2.” Diffusers' SDXL default already selects that layer. The import records the publisher's modified Fair AI Public License 1.0-SD and leaves commercial use marked for review.

Playwright mounts the production Media Studio, submits through its generation controls, and calls the real Tauri backend through the existing desktop bridge. Model inference, asset storage, and export are real. Recipe setup is automated; file-picker responses are controlled by the harness.

The SD 1.5 PNDM scheduler performs 25 evaluations for a 24-step text-to-image request, and image-to-image uses a shorter schedule. Progress now uses the pipeline's effective timestep count rather than showing values such as `25/24` or stopping at `16/24`.

The first lower-influence Pony trial found a submission bug: Basic promoted the first reference to the source-image node with hardcoded influence 1. Selecting 0.25 therefore produced a byte-identical result, and the runtime evidence correctly recorded influence 1. Basic now preserves the first reference's influence, including conversion to Advanced. Regression tests cover independent strengths with and without a base image. The `pony-reference-weak` artifacts document the faulty submission; they are not evidence about low-strength IP-Adapter behavior.

Masked edits previously decoded every base as RGB, discarding any existing alpha channel. The worker now keeps the original RGBA canvas for final compositing while supplying RGB crops to the model. A regression test checks every channel outside the selection, including varying transparency. The [FLUX.2 regression](../apps/client/.cache/media-models-2026-09-15/flux2-mask-transparent-regression-after.png) changed the lid to blue and preserved every RGBA pixel outside the selection. Painting over transparent space can produce an opaque patch inside the selection; this is visible in the test and requires a more precise mask or a subsequent cutout. FLUX.2 was also reprobed successfully against the updated worker.

The desktop's automatic development rebuild required reconnecting the test bridge. After reconnecting, native preview responses arrived as byte arrays; the harness initially expected an ArrayBuffer, causing preview-only failures. The bridge serialization was corrected. The exported images and alpha measurements remain valid; screenshots with unavailable-preview icons are not visual evidence of a working preview. Some optimistic run-detail reads also returned “not found” before the run was registered, then subsequent reads and exports succeeded.
