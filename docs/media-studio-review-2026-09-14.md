# Media Studio review — 14 September 2026

Media Studio produced real KREA2 images with and without a LoRA, a short Hunyuan video, and FLUX reference and mask edits on this Windows/AMD machine. The complete nontechnical journey still has blocking gaps: model acquisition requires manual work, Basic text-to-video builds an invalid flow, painted masks can fail before generation, and results lack a save action. Fresh runtime setup, dependency repair, and reuse passed; recovery from a damaged environment directory failed.

## Method and environment

Playwright drove the actual `MediaStudio` React component from the running Vite application, with its commands and events connected to the running Tauri desktop backend through the installed MCP bridge. Generation, model inspection, database writes, runtime installation, and asset decoding used the real implementation. The surrounding chat shell and remote provider configuration were excluded. File dialogs received predetermined local paths; the Windows file-picker interaction itself was not tested. No development server was started or restarted.

The machine has an AMD Radeon RX 9070 reporting 15.92 GiB VRAM, an integrated AMD adapter, and 31.31 GiB physical RAM. The managed runtime selected the discrete GPU and installed Python 3.12.10, Torch 2.12.0+ROCm 7.14.0, Diffusers 0.39.0, Transformers 5.13.0, Accelerate 1.14.0, and PEFT 0.19.1. Other applications were running; available RAM fell below 2 GiB during the Wan attempt. The browser/native bridge also adds overhead. Timings describe these attempts, not controlled performance benchmarks.

The checkout contained existing changes, including concurrent interface work. This review does not attribute those changes or modify product code. The Python worker used by the native app matched the inspected source by SHA-256 (`d0f0789229b499aa049b0276aee9048ff60abfbe826c2a84628e5a7be8dcab78`). Browser snapshots, harness scripts, model inspection results, run records, and copied output files are under `apps/client/.cache/media-review-2026-09-14/`.

## Problems and minimal improvements

1. **P1 — A completed result has no explicit save/export action.** Basic results offer **Edit image**, **Animate**, and **View in Assets**. Asset details and their menu offer reuse, settings, organization, and deletion. None exposes the existing `exportMediaAsset` backend operation. This leaves the last step of the journey incomplete even when pixels are good. Add **Save image/Save video** to results and asset details, using the existing export implementation. Evidence: snapshots 58–60; `media-generate-view.tsx:1790`, `media-assets-view.tsx:650`, `media-runtime.ts:3657`.

2. **P1 — Runtime setup does not acquire a usable model and its complete dependencies.** The model library hides uninstalled built-ins and exposes no install/download or removal action. A new user must obtain files externally. KREA2 additionally expects a specific Qwen directory structure and approximately 9 GB of components; the import backend rejects missing components with a technical folder instruction. The audit supplied that bundle manually before the successful render. Connect model acquisition and component installation to the existing model lifecycle, choose a feasible default for the hardware, and download the dependencies of an imported checkpoint automatically. Preserve review of any actual access/license requirement at acquisition. Evidence: `model-library.ts:82`, `model_import.rs:533`, `media-assets-view.tsx:500`.

3. **P1 — Ordinary text-to-video creates an invalid transparent/composite workflow.** In Basic, a prompt with no starting image and **Transparent background** off leaves Generate disabled with “Resolve the local video model, runtime, and node contract diagnostics first.” Converting to Advanced exposes “Animated background compositing requires transparent foreground extraction.” `createCurrentVideoFlow` uses the generated-character-loop template, which always adds background removal, a transparent output, and an animated-background composite. Build the graph for the requested output; an ordinary opaque video should not require those operations. Prefer native text-to-video where supported, or automatically generate the required first frame. Evidence: snapshot 66; `media-studio.tsx:2080`, `compiler.ts:709`.

4. **P1 — Basic Draft is not the Advanced Draft preset.** Basic sets resolution/frame count/fps, but both video flow builders hardcode 30 sampling steps, production matting, and lossless encoding. Conversion labels the node **custom**; Hunyuan resolves to 12 steps until **Draft** is clicked again in Advanced, which correctly applies 8 steps and balanced encoding. This adds avoidable waiting and makes the same quality label mean different work. Carry one complete preset through Basic, graph conversion, and execution. Evidence: snapshots 66, 69–70; `compiler.ts:597`, `compiler.ts:783`, `video-quality.ts:38`.

5. **P1 — Repair cannot rebuild a damaged environment directory.** Running the actual installer against an existing isolated test root whose `environment` directory lacked `pyvenv.cfg` failed with “uv will not clear a directory that is not a virtual environment.” Its `Lib`, `Scripts`, and test sentinel were still present; the origin of that partial state was not established. The installer always uses `uv venv --clear`, so retrying does not recover this state. Recreate the managed environment after validating its exact managed path, preserving model and asset storage. Evidence: `runtime-repair-live.log`; `runtime_setup/installer.rs:193`. This is distinct from ordinary missing-package repair.

6. **P1 — Painting a mask can make Basic generation fail its own saved-flow validation.** Runs `b53a26c6-8355-48f3-a0ee-c24a498aa108` and `cb6f2759-efc9-43fa-bb1b-0debd8d1101e` were rejected before a native run record or model worker was created. One submitted stroke coordinate, `0.21999999533540318`, became `0.2199999953354032` in the saved revision. The submitted execution digest (`d560a0…`) then differed from the stored digest (`56b0ee…`). The interface says only “Some media settings are invalid”; **Reuse settings** repeats the failure. Use consistent numeric canonicalization across the frontend/backend and compile the canonical saved revision, retaining the lineage check. Add a boundary regression using the captured stroke. Evidence: `mask-coordinate-roundtrip.json`, `captured-conditioning-requests.json`, snapshots 92–100; `canonicalize.ts:90`, `flow.rs:5033`, `database.rs:5754`.

7. **P2 — A failed model check has no useful recovery diagnosis.** Setup finished as ready while FLUX.2 klein verification failed loading components. The library says “Correct the reported model issue, then verify again,” but the diagnostic only contains loading progress bars. This initially blocked the reference/mask model. A later **Verify model** retry passed in approximately 80 seconds without changing packages or model files; the initial exit's cause was not established. Capture the exit code and useful last stage, and offer a clear retry or repair action appropriate to the failure. Do not direct users to fix an unspecified issue. Evidence: `catalog-ready.json`, snapshots 57, 88–91; `provider_local_diffusers.rs:1206`, `runtime_setup/mod.rs:155`.

8. **P2 — Embedding import hides a required input and reports the wrong recovery.** `EasyNegative.safetensors` is recognized, but **Import embedding** accepts a blank token. The backend returns `INVALID_REQUEST`, “token is required for textual-inversion embeddings,” while the interface says to check the file and storage. Derive a token from reliable metadata or the filename; otherwise require it in the existing field and validate before import. Evidence: `embedding-inspection.json`, snapshots 12–14; `media-asset-import-dialog.tsx:486`, `model_addon.rs:1303`.

9. **P2 — Reference/mask selection can end at an empty model picker.** The compatibility filter correctly prevents KREA2 from being used for unsupported image conditioning, but users see **Choose a model** and a disabled picker when FLUX is unavailable. Offer the specific compatible model’s setup/verification action at this point, and select it once ready. Do not require users to infer pipeline support from architecture names. Evidence: snapshots 51 and 71–72; `media-generate-view.tsx:232`, `media_diffusers_worker.py:2565`.

10. **P2 — Long work reports a fixed percentage instead of useful progress.** The successful KREA2 render stayed at 10% through almost the entire 11-minute job. Runtime/model loading, memory preparation, sampling, and encoding are not reflected in the displayed stage. Stream bounded progress from the worker, show elapsed time, and retain cancellation. The worker runner also waits for exit before draining stdout/stderr; sufficiently verbose output can block a child on a full pipe. That pipe risk is from code inspection, not an attributed cause of the completed KREA2 run. Evidence: run events; `provider_local_diffusers.rs:604`.

11. **P2 — Discovery and management remain incomplete.** Workspace package discovery made Wan and Hunyuan selectable, but discovered checkpoints/add-ons are not automatically registered as imported library entries. Discovery is refreshed on workspace/component initialization rather than through a visible rescan or file watcher. A large checkpoint is inspected as an add-on and then again as a model, including repeated full-file hashing. Uninstalled built-ins are hidden, and model/add-on removal is absent. Recognize headers once, reuse a checked content identity, refresh after file changes, and expose the existing lifecycle actions where needed. Evidence: `model_discovery.rs:940`, `model-library.ts:82`, `media-studio.tsx:1254`.

12. **P2 — SVG import silently changes the asset type.** The dialog recognizes an SVG, but calls the image importer, which rasterizes it to PNG. The resulting item is absent from **SVGs** and no vector original is published. Preserve the sanitized SVG as the imported asset and create a raster derivative only when image conditioning needs one. If raster-only import is intentional, make that consequence explicit at import. Evidence: snapshots 80–82, run `import:adf2988eedf65c93:1789341490847222600`; `media-runtime.ts:2797`, `database.rs:684`.

13. **P2 — The mask editor does not preview the output framing.** The editor showed the full portrait, but FLUX's square output center-cropped and resampled the whole source before pasting the changed region. Unselected pixels are preserved only relative to that transformed source. Preserve the original canvas for a localized edit, or make the editor use the actual output framing. Automatically adopting source framing would also avoid the video test's gray side bars when a square output is not intentional. Evidence: `render-mask-overlay.png`, `7db49331-230b-4c38-a7c4-e45966a5b88f-0.png`, `masked-image-inspection.json`; `media_diffusers_worker.py:2374`.

14. **P3 — Several labels still assume specialist knowledge or show the wrong context.** The graph exposes “execution boundary,” “exact model pin,” “native 4k+1 contract,” schema/digest details, and repeated implementation descriptions even on its Basic tab. Source images appear as “Image 1,” “Image 2,” etc. rather than their imported filename, and the asset card's animate icon has no accessible name. The Hunyuan run's generic Output setting says **1 × PNG**, although its video is WebM. Preserve filenames, label the icon, show the actual media format, and remove redundant technical copy. Keep useful dimensions, duration, quality, compatibility, and failure information. Evidence: snapshots 41, 45, 54, 69, 86; `media-assets-view.tsx:760`, `media-runs-view.tsx`.

## Checks and limits

- The runtime, downloaded test assets, audit tags/categories, and saved audit flows remain locally available. The isolated installer test directories also remain in Windows Temp. Existing user models and assets were retained.
