The first two fresh attempts stalled in prompt weight loading before denoising. Stack samples located the work inside Transformers' tensor materialization and FP16-to-BF16 conversion, with heavy Windows page faults. Disabling asynchronous loading alone still incurred substantial loading pressure and was not retained as the solution.

The replacement loader reads Safetensors tensors through the `pread` backend, converts one tensor at a time, and validates the complete parameter set against the model and shard index. FramePack transformer loading uses the same file-reading backend. The isolated worker loads its companion by absolute file path. Tests verify every parameter and prompt output on a sharded model and exercise the actual isolated-process import. These changes address loading; visual generation and loop acceptance are assessed separately.

That attempt passed prompt loading but spent several minutes per endpoint in the existing AMD CPU image-encoder path. It then crashed at the first denoising step with Windows exception `0xC0000005`; the native stack includes the CPU allocator and tensor conversion. This attempt produced no new frames. A concurrent desktop rebuild also failed, and the native bridge subsequently became unavailable. The trace does not establish the underlying cause of the access violation. [Log](../apps/client/.cache/wan-framepack-nodes-2026-09-15/framepack-bounded-load-fixed-import.log).

The image encoder now uses staged GPU execution and returns to CPU afterward. AMD retains FP32 image-encoder weights. With the existing convolution backend configuration, the actual Siglip patch convolution agreed with CPU to approximately `4.18e-7` mean relative error. This bounded probe does not by itself establish full video quality. [Probe](../apps/client/.cache/wan-framepack-nodes-2026-09-15/siglip-patch-evidence.json).

The restored package's large weight files match their pinned publisher hashes. Small configuration files were downloaded from the pinned revisions and their local hashes recorded; the verification script did not compare Git blob hashes for those files. The existing FP8 cache format was prepared locally to avoid repeated transformer conversion during the next render. [Package verification](../apps/client/.cache/wan-framepack-nodes-2026-09-15/framepack-package-verification.json), [cache preparation](../apps/client/.cache/wan-framepack-nodes-2026-09-15/framepack-cache-preparation.json).

A separate timing defect was then identified in the low-memory VAE configuration. Its six-sample-frame stride is divided by the VAE's four-frame temporal compression when advancing latent tiles, but the decoder still emits six frames per chunk. A test using the installed [Diffusers temporal decoder](https://github.com/huggingface/diffusers/blob/v0.39.0/src/diffusers/models/autoencoders/autoencoder_kl_hunyuan_video.py) reproduces the resulting timeline distortion: a 37-frame linear trajectory ends ten frames early. The corrected four-frame stride reproduces the complete trajectory exactly. Worker 1.68.0 applies this correction, with a regression test covering the configured memory profiles. This establishes a decoder configuration defect; the corrected real render and its loop result must be assessed separately. [Timing evidence](../apps/client/.cache/wan-framepack-nodes-2026-09-15/framepack-temporal-tiling-evidence.json).

The 12–23 GiB profile also uses 128-pixel spatial tiles instead of 64-pixel tiles. On the tested 16 GiB adapter, a nine-frame, 640×640 decode probe completed in 25.9 seconds with 3.01 GB peak allocation. This probe used random latents to measure memory and dimensions; it is not evidence of generation quality. Smaller GPUs retain 64-pixel spatial tiles, and the larger-GPU profile retains its existing 256-pixel tiles. All profiles now use temporal strides aligned to the VAE's compression. [Probe](../apps/client/.cache/wan-framepack-nodes-2026-09-15/framepack-128-tile-profile.json).

All four last-two/first-two crossings were captured and viewed for each clip. Raw playback has a pose reset; crossfade improves the file boundary but retains its rejected interior transition. ## ComfyUI node coverage

Machdoch uses its own typed graph, native executor and Diffusers workers. It does not run a ComfyUI server or import arbitrary ComfyUI workflow JSON. The additions below implement the relevant node operations in that graph; they do not install or execute entire custom-node packs.

Selection combines workflow relevance with available adoption evidence. Canny and depth ControlNet appear in [ComfyUI's ControlNet documentation](https://docs.comfy.org/tutorials/controlnet/controlnet). The [ControlNet auxiliary preprocessors](https://github.com/Fannovel16/comfyui_controlnet_aux), [KJNodes](https://github.com/kijai/ComfyUI-KJNodes), [Impact Pack](https://github.com/ltdrdata/ComfyUI-Impact-Pack), and [VideoHelperSuite](https://github.com/Kosinkadink/ComfyUI-VideoHelperSuite) have substantial repository adoption. Repository stars indicate interest in packs; they are not measurements of individual node usage. A defensible per-node usage ranking was not available.

| ComfyUI operation or family                                       | Previous Machdoch coverage                    | Change / scope                                                                                                                           |
| ----------------------------------------------------------------- | --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Model loading, CLIP prompts, sampling, LoRA and textual inversion | Existing local generation and add-on paths    | Retained; regression checks include Pixel M and all eight EasyNegative vectors                                                           |
| Image input, crop, resize, color, sharpen and composite           | Existing native image operations              | Retained                                                                                                                                 |

New templates generate from edges or depth. Invalid control ranges, incompatible models, mismatched ports, and simultaneous pose plus edge/depth controls are rejected before generation. Model dependencies have pinned revisions, sizes and SHA-256 checks; the packaged Python resource list includes the new workers. The existing managed environment supplies OpenCV, Transformers and Safetensors.

The live desktop palette exposes all five additions. Reviewing an eleven-node editing graph exposed overlapping image cards and preprocessing nodes placed after the generator. Automatic and template layout now follow graph connections with sufficient card spacing. The live graph measured zero overlapping node rectangles. [Palette](../apps/client/.cache/wan-framepack-nodes-2026-09-15/node-palette-ui.png), [graph](../apps/client/.cache/wan-framepack-nodes-2026-09-15/mask-controlnet-graph-ui.png), [measurements](../apps/client/.cache/wan-framepack-nodes-2026-09-15/graph-layout-measurement.json).

Remaining scope excludes arbitrary ComfyUI JSON/custom-pack execution, stacked ControlNets, SDXL/FLUX/video ControlNet variants, mask offsets and the other MaskComposite operators, RIFE interpolation, VACE, and additional detector/preprocessor models. This work does not claim that every popular node is supported.
