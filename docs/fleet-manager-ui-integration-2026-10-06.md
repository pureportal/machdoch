# Fleet UI integration — 2026-10-06

The client, Fleet dashboard, and remote device view share the application frame, navigation, appearance controls, and palette. The complete goal of exposing every client feature remotely remains open.

The latest continuation, TLS checks, corrected feature coverage, and remaining gaps are recorded in [the parity audit](fleet-manager-parity-audit-2026-10-06.md). The tables below record the earlier campaign; their pending items are superseded by that audit.

## Changes

- `packages/product-ui` owns `ApplicationShell`, `ApplicationNavigation`, `AppearanceOptions`, and appearance normalization/application. Native Chat, Fleet's dashboard, and Fleet `ProductShell` compose these components. Fleet-specific palette overrides were removed.
- Native and remote Instructions use the same editor, tag rules, validation, command palette, and management hook in `packages/client-ui`. Their models and mutation serialization live in `packages/fleet-protocol`. The remote view supports creation, editing, preview, duplication, deletion, and library recovery, preserves drafts across navigation, and keeps the revision the user reviewed for conflict detection.
- A scoped Instructions protocol routes operations to the canonical instruction library on headless hosts and to the existing desktop command handler on native hosts. Global library editing works without an active workspace; operations referring to workspace roots require roots listed on the device. Authentication, CSRF, capability checks, response correlation, and revocation apply to the relay.
- Native and remote Smart Scheduler share the complete form, job/run views, mutations, confirmations, and command palette. The scoped Scheduler protocol replaces the incomplete Inspector Scheduler command path, which was removed.
- The canonical headless scheduler service limits concurrent workspace workers, rotates polling order, discovers workspace changes, imports scheduled prompt definitions, and resumes interrupted durable runs after restart. Native service-all and the headless Fleet runtime use this service.
- Headless Fleet persists per-session global-memory changes and honors them in subsequent task context. Replayed product commands retain their receipts after restart.
- The remote view now embeds the canonical native Workspace Manager with Output, Configuration, Files, Git, Memory, and Settings. Its transport delegates to the existing native handlers. File drafts survive navigation, reviewed revisions protect edits, and workspace settings reload the actual saved snapshot. Real native API checks cover configuration, memory, ReasoningBank, reviewed MCP documents, and process start/output/restart/stop. The six-panel production browser campaign passed real saves, conflicts, configuration, process start/restart/stop, Git branch creation, terminal input/output, and desktop/mobile overflow checks.
- Remote terminals use bounded output and cursor acknowledgment. Real simultaneous local/remote PTYs passed remote stop, lease expiry, and gateway disconnect without stopping the local terminal.
- Workspace creation, removal, and relinking use the canonical instruction lifecycle and recent-workspace handlers. Both views register workspace add and settings save shortcuts.
- Remote voice controls now dispatch auto-speak and device microphone commands. Native recording and busy state are included in the strict gateway snapshot; contract and shared composer tests pass. Live auto-speak persistence, actual recording/busy state, microphone stop, duplicate receipts, and unknown-session rejection passed. Physical recording and playback were not performed.
- Native run previews use the existing run manager and declared ports. The gateway validates preview targets before opening private TCP/WebSocket tunnels. The shared run panel routes local URLs through Fleet previews and preserves paths and queries. Native compilation and manager path validation pass; live native tunnels remain unverified.
- Native and Fleet settings use the same SettingsDialog, panels, runtime controls, appearance options and device voice projection. The closed DeviceSettings protocol delegates to canonical native handlers and reports UI persistence errors before confirming changes. Remote settings open over Chat without discarding the browser draft.
- Encrypted settings export/import uses native encryption, review/conflict handling and the existing bounded file-transfer grants. The browser downloads and uploads files through those grants. LAN transfer uses native status polling and settings-import events. Asset storage reads, migration and resume use the canonical native Media storage handlers.
- MCP provider-sync controls use the workspace relay and canonical native command handler. Remote browser previews no longer return fabricated provider-sync status. Native retry and adaptive-controller settings now persist their previously omitted configuration fields.
- Instructions registry/content/recovery now use one canonical CLI query, removing the duplicate slow query that delayed remote workspace updates.
- The standalone HTTP server applies validated operation body budgets to Instructions, Scheduler, Workspace and DeviceSettings routes.

## Remaining work and limits

The browser campaigns use offline CLI hosts, fixture API keys, and browser mobile viewports. Native verification uses an isolated desktop profile and a real authenticated gateway fixture over debug loopback HTTP. Native enrollment, settings synchronization, and Instructions control are now verified. Provider-backed AI completion, voice input/output, GPU generation, physical Android behavior, and native production TLS enrollment remain unverified. No development server was started.

Full application keyboard bindings need parity verification. The missing remote features in the coverage table remain implementation work. Full outcome completion is not claimed.
