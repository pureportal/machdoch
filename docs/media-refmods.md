# MiniMax H3 RefMods

The integration targets Machdoch's `local:minimax-h3-ref2va` runtime. It stores and reuses native H3 image, video and audio conditioning. Completion requires both software checks and a licensed real-model generation comparison; synthetic tensor tests alone do not establish generation quality.

## Workflow

Install the Media Studio runtime, then open Video → RefMods to create, import, inspect, preview and export references before installing the generation model. Library opens the workspace's saved references directly; Browse folder opens another collection. Creation and imports keep workspace copies under `models/refmods`, so their sources can be removed. The standalone panel retains its selection when closed and keeps generation settings separate. Once the generation model is installed, choose MiniMax H3 to attach references to a run. Inspect lists members and token costs; optional previews show a selected video frame, an image or two seconds of audio, with a strength comparison. The frame picker shows the sequence length, excludes decoder padding and resets when the selected member changes.

Creation and preview need the VAE for the selected modality, independently of generation weights. Put `minimax_h3_audio_vae_fp32.safetensors` or `minimax_h3_video_vae_fp16.safetensors` in `models/minimax-h3-ref2va/vae`. Native discovery accepts a VAE-only package; generation still requires the complete Ref2VA package. Mixed creation checks both paths and checkpoint headers before loading either model. Missing VAEs and invalid, empty or truncated checkpoints return installation recovery with a modality-specific message. The video weight-memory check returns GPU-capacity recovery. Worker paths stay in technical diagnostics. Discovery runs with the worker task, outside the UI command's async body.

The creator shows original filenames and can be closed with Close creator. Remote uploads are released when a source or mask is removed, a mask is replaced, or the creator closes; closing waits for pending work to finish. Failed creation preserves its inputs for retry and releases its output reservation. Batch import releases every selected upload, including files following an invalid file. Unreadable references offer a file-selection recovery instruction. Native file selections preserve the original files.

Both VAEs use the native Diffusers H3 architectures. The runtime installs commit `4295ee3ec58efa6577bc459e9b84ca3f63aa9a96` from a source archive with SHA-256 `b8797a69784b365643a1935b5b82df679873068c8a3077e363a266a8f62f5c8f`, avoiding Git checkout failures in long Windows application paths. Video loads only the requested encoder or decoder, accepts the released fp16 normalization statistics, and converts per-head QKV and gated feed-forward weights to the native layout. It retains fp32 weights with fp16 GPU autocast, as required by the pinned architecture. Decoder weights require 9,694,132,576 bytes (9.03 GiB) before activations; the previous port used approximately half that memory. The loader checks free GPU memory before reading model weights and reports insufficient capacity. Real-checkpoint peak memory and quality remain to be measured.

Each slot supports enablement, ordering, modality selection, independent visual/audio strengths, copies, and curves over denoising steps or reference frames. Preview loads only the selected member's tensor, preserving its dtype, and checks its fp32 memory cost before allocation. Audio metadata, when present, must identify the 32 kHz H3 codec. The standalone panel shows reference-frame curves for export; generation adds denoising curves and numbered prompt buttons for the encoder's mapping. References can accompany one image or supply all conditioning without an image. Generation settings survive saved recipes and flow revisions.

Creation supports per-source masks and clip offsets, dimensions, full or compressed visual latents, spatial grid size and temporal length, optional latent refinement, video frame limits, audio duration, names and descriptive metadata. Compression reduces video to at most three latent frames by default; the advanced controls allow 1–107. Source folders collect supported files in filename order. The creator saves only after all extraction and token checks succeed. Existing destinations are preserved; choose a new name to save another version.

Export saves the selected modalities and copies, with the static strength and reference-frame curve baked into each latent. Denoising curves remain recipe/flow settings; export does not bake a dynamic curve into a single latent. Preserve a flow to share the complete run configuration. Remote creation keeps a library copy before downloading and removing its transfer file.

RefMod creation and preview commands can be canceled and have a thirty-minute worker timeout. Cancellation stops queued or running workers; native operations own their temporary reservations so cancellation and errors can remove them. Cancellation requested during runtime preparation is applied when preparation returns.

## Coverage and boundaries

| Requirement                  | Implementation                                                                                                                                                                     | Verification                                                                                                                                                                               |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Image, video and audio files | Standalone v4 and ordered v5 safetensors bundles, including independent shapes                                                                                                     | CPU round trips, header/shape validation and mixed-bundle native worker import/export                                                                                                      |
| Native H3 conditioning       | Video patch projection; channel-major stereo audio projection; native positions, tags and clean timesteps                                                                          | Tiny DiT joint denoising on CPU and AMD GPU with finite audiovisual outputs                                                                                                                |
| Prompt references            | Picture, Video and Audio numbering follows active members and copies, with audio after visuals                                                                                     | Mapping tests; real-model binding still needs comparison                                                                                                                                   |
| Usable editor                | Create/import/browse/batch inspect/export, strengths/copies/curves, optional previews                                                                                              | Actual desktop UI, native file/mask/save dialogs, authenticated fleet browser upload/download, and recipe/flow tests                                                                       |
| Creation and compression     | Native Diffusers H3 VAEs, masks, bounded clips/audio, pooling and optional latent MSE refinement                                                                                   | Native video architecture/conversion/frame tests and released-header compatibility passed; historical pretrained audio checks passed; licensed pretrained video validation remains pending |
| Persistence and transport    | Recipes, flows, typed Rust request fields, worker command, fleet dispatch and permanent imports                                                                                    | Visible desktop and fleet import/export and reopening passed; successful pretrained creation, preview and generation remain pending                                                        |
| Reliability                  | Finite tensors, strict shapes and metadata, resource caps, pre-load token checks, stable-file checks, atomic publication without overwrite, cancellation and owned temporary files | Invalid data, interrupted save, restart, selection, native process cancellation, 15 error-contract checks and visible desktop/fleet recovery                                               |
| Research and attribution     | Primary upstream formats and code studied; full MIT licences, modification notice and model terms retained                                                                         | Exact licence hashes and both release bundles verified; model authorization and GPL provenance remain unresolved                                                                           |

Limits: at most 256 slots/active blocks, 1–8 copies, 512 MiB per file and accumulated fp32 conditioning, 1 MiB of metadata, and a configurable token budget (65,536 by default; zero disables the token cap). Collection inspection uses bounded pages and omits descriptive metadata; individual inspection preserves it. Visual shapes are `[1,24,T,H,W]` with even spatial dimensions; audio shapes are `[1,32,2,T]`. Visual token cost is `T*(H/2)*(W/2)`; audio cost is `2*T`. The optional image contributes to the total conditioning budget.

Video creation reads a bounded contiguous segment at 24 fps, starting at the requested offset. Frame limits follow `17n+5`. It does not silently subsample the entirety of a longer movie. Audio is normalized stereo at 32 kHz, encoded in bounded ten-second chunks; chunk boundaries can affect continuity. Input masks use the same center crop as their visual source.

Qwen receives up to eight representative frames reconstructed with the temporal decoder, spanning a video's saved sequence. Compressed video may have any positive temporal length; presentation pads its final latent to a decoder clip boundary and uses the native frame clock to exclude the padding from its sample range. The DiT receives the original selected latent, including its temporal sequence. This bounded presentation is an approximation, not exact native preprocessing of the original source. Visual presentation/preview requires a latent grid of at most 128 per axis (2048 decoded pixels). Selected-frame decoding uses at most two temporal chunks; CPU tests match full native decoding exactly across chunk boundaries. Still images and five-frame clips explicitly handle the native decoder's minimum chunk length. Pretrained visual quality remains unverified.

Compression refines only the small latent against its enlarged reconstruction, without training the DiT or learning an identity. A zero slot strength skips its modality; a zero curve value keeps blurred conditioning and its tokens. Curves describe the reference sequence or denoising progress, not events on the generated video's timeline. No claim is made for reliable voice cloning, identity isolation or exact motion reproduction.

- [Fantastic MiniMaxH3 PromptBuilder RefMods](https://github.com/Adudeguyman/ComfyUI-Fantastic-MiniMaxH3-PromptBuilder/blob/main/REFMODS.md): reference prompting, native workflow comparisons and quality limitations.
- [ComfyUI's native H3 model](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy/ldm/minimax/model.py) and [reference nodes](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy_extras/nodes_minimax_h3.py): packed reference order, stereo positions, modality tags and conditioning timesteps.
- [Diffusers' native H3 integration](https://huggingface.co/docs/diffusers/main/en/api/pipelines/minimax_h3): ordered mixed references, separate video/audio schedules, component loading and offloading. Its full checkpoint and Qwen3-VL conditioner differ from this runtime's pruned INT8 transformer, smaller conditioner and turbo adapters. The repository-local unit-test runtime's Diffusers 0.39.0 does not expose `MiniMaxH3Transformer3DModel`; the separately managed runtime's 0.41.0.dev0 does. A backend replacement still needs checkpoint/adapter compatibility and real-model verification; class availability does not establish those or resolve this runtime's existing GPL provenance.
- Diffusers' [video VAE](https://github.com/huggingface/diffusers/blob/main/src/diffusers/models/autoencoders/autoencoder_kl_minimax_h3.py) and [audio VAE](https://github.com/huggingface/diffusers/blob/main/src/diffusers/models/autoencoders/autoencoder_kl_minimax_h3_audio.py) carry Apache 2.0 headers. Their architectures now replace both former VAE ports. Research used the official [conversion script](https://github.com/huggingface/diffusers/blob/main/scripts/convert_minimax_h3_to_diffusers.py): original audio names, video per-head interleaved QKV, feed-forward ordering, normalization and native temporal tiling. Random-weight forward checks and the released video header validate the implemented conversion without using pretrained tensor values. The current native managed installer passed setup, imports, GPU computation and FFmpeg encoding in 406.33 seconds; the live app subsequently reported Ready. An earlier separate D-drive runtime had a fourteen-minute import delay involving SciPy and Windows file queries; that observation does not establish the behavior of the new installation. The transformer and sampler still retain the recorded GPL provenance.

This integration implements the native conditioning path directly. ComfyUI-specific graph bridges, signed axis widgets, scrambling, legacy sidecars and graph-PNG preset formats are not implemented. Order, selection and saved flows provide Machdoch's corresponding workflow controls; this is not a claim of one-to-one node parity.

## Licensing and release blockers

[NOTICE-RefMod.txt](../apps/client/src-tauri/python/NOTICE-RefMod.txt) identifies the inspiration and the modified Fizgig model. The full upstream MIT texts are retained and included by the release licence generator. The downloaded [MiniMax-H3 licence](../legal/third-party/MiniMax-H3/LICENSE) has SHA-256 `59b99642b95ea21630e311198ddbfffbfe05aadba0c2f5d884cbdf4efcc90f44`; its required [NOTICE](../legal/third-party/MiniMax-H3/NOTICE) is retained separately.

The model licence grants rights within its applicable territory, excluding the EU, UK, US and South Korea. Separate MiniMax authorization is necessary outside that territory and for commercial revenue above its threshold. It also imposes redistribution, downstream-use, safeguards and commercial UI obligations. Installing this integration does not establish permission to obtain, test or use H3 weights. A deployment's location, authorization and downstream terms have not been verified.

The remaining Fizgig MiniMax transformer and sampler have unresolved ComfyUI GPL provenance, as recorded in [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md) and [legal/README.md](../legal/README.md). Replacing the audio and video VAEs and retaining MIT inspiration notices do not resolve those combined-work obligations. Model authorization and code-distribution provenance remain release blockers.
